Run a node

Run your own supernode.

A supernode is a Linux machine you operate. It can relay connections and host rooms for the people you invite. It is not an account system, and it cannot read sealed chat, voice, or files. Use a server you already have, or rent one from any provider. You keep the machine. DoubleSlash does not operate it.

What the server needs

  • A Linux machine with a public IPv4 or IPv6 address. Published supernode packages cover 64-bit Intel or AMD, and ARM64.
  • SSH from the computer you will install from. The desktop setup can turn password login off after a key login works. The password is used once and is not stored. This website never asks for it.
  • The relay UDP port and the signaling TCP port open to the people who will use the node. The usual defaults are UDP 3478 and TCP 34935. The setup shows the ports it will use.
  • No public web port. Portal pages open inside the DoubleSlash app, not in a browser pointed at the server.
  • A second server later, if you add one, keeps its cluster port closed to the public and open only between those servers. The usual cluster port is UDP 4478.

The desktop path is Settings, then Network, then Your servers. Its firewall and automatic security-update steps are written for Debian 11 and Ubuntu 20.04 or newer. You can also install a published Linux package yourself. Nightly supernode builds are pre-release and can change.

After the machine exists

  1. Note the public address and an admin login.
  2. Install the supernode from the desktop app, or follow the operator guide. Packages are on the releases page.
  3. Read the responsibility notice before the first install. You remain responsible for the server: its cost, security, updates, backups, and the law where you live and where it runs. DoubleSlash does not operate it.
  4. Connect with the node’s own invite. A new server does not join you to anyone else’s network. The server is not a DoubleSlash identity, and neither is the company that rents it to you.
