Set up your server

  1. Choose a Linux server with a public IP address and SSH access. The desktop setup is designed for Debian 11 and Ubuntu 20.04 or newer.
  2. Open Settings > Network > Your servers in the desktop app and follow the setup steps. It installs the nightly supernode build, which is pre-release.
  3. Accept the node’s invite, then share it with your group.

Server costs, security, updates, backups, and legal responsibilities remain yours.

Server and network requirements
  • Use a public IPv4 or IPv6 address. Linux packages support 64-bit Intel/AMD and ARM64.
  • Setup shows the required ports, usually UDP 3478 for relay and TCP 34935 for signaling. No public web port is needed.
  • For a cluster, keep its private connection port restricted to members, usually UDP 4478.

Keep connections working after an IP change

Give the supernode a hostname in Your servers > Set hostname. Clients that have connected since, and invites shared after it is set, look the name up when the IP address stops answering. Older invites do not gain the name. The node still has to prove its identity, so a name cannot hand trust to a different server. A name is optional; IP-only invites keep working while the address stays the same.

  • Your domain: choose DNS and point an A or AAAA record at the server. Clients keep the signaling port they already know.
  • Your website: choose DDDNS and serve a JSON record at https://your-name.example/.well-known/doubleslash over HTTPS, with no login or redirect. See the record format.
  • DoubleSlash DDNS: a name under doubleslash.space, described below.

You keep the DNS record or JSON file current yourself.
